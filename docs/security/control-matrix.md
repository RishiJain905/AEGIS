## Configuration notes

- `AEGIS_REQUEST_BODY_MAX_BYTES`, `AEGIS_RATE_LIMIT_REQUESTS_PER_MINUTE`, `AEGIS_RATE_LIMIT_BURST`, and `AEGIS_RATE_LIMIT_MAX_BUCKETS` are process-local enforcement settings with safe development defaults.
- The limiter enforces both IP and hashed-session buckets, so rotating an arbitrary cookie cannot bypass the IP bound. Bucket state uses deterministic least-recently-used eviction at the configured cap.
- The rate limiter intentionally adds no Redis authority or availability dependency. Multi-process deployments receive a per-process bound and should size limits accordingly.
- `AEGIS_SECURITY_HSTS_ENABLED=false` is safe for HTTP local development. Production TLS deployments should enable it after confirming all covered hostnames support HTTPS.
- The web CSP permits `'unsafe-inline'` for Next.js bootstrap/hydration and inline styles used by Next/React/Radix/Sigma. It does not permit remote script origins; `object-src` is disabled and framing is denied. Development alone adds `'unsafe-eval'`. A nonce-based Next middleware is the future tightening path if config-only headers are no longer a constraint.
- `worker-src 'self' blob:` supports bundled graph layout workers; `img-src data: blob:` supports graph/canvas assets; `connect-src` is limited to self plus configured API/WS origins.
- `api`, `web`, `worker`, and `simulator` run with `read_only: true`, `cap_drop: [ALL]`, and `no-new-privileges:true`. Their Dockerfiles set `HOME`/`TMPDIR` to `/tmp`; the Compose `/tmp` tmpfs is the only expected writable runtime path and uses `noexec,nosuid` with a 64 MiB bound. No capability is added back because all application ports are above 1024.
- PostgreSQL, Redis, MinIO, and the observability services retain their existing writable data volumes and upstream runtime defaults. Their storage and initialization behavior make a blanket read-only/capability policy unsafe for this local stack; they remain included in the threat model and should receive service-specific hardening before production deployment.
- `security.yml` intentionally does not repeat `pnpm audit`, `pnpm audit signatures`, `pip-audit`, or gitleaks; those controls remain in `ci.yml`. Semgrep errors, Trivy high/critical IaC findings, and fixable high/critical image vulnerabilities are blocking. License output is an artifact-only report under the exception and triage contract.
- Scanner container references in `security.yml` use version tags plus immutable image digests. Checkov's repository-owned `CKV_AEGIS_1` is the Compose-specific policy because Trivy's built-in config scanners do not recognize Compose files; secret scanning is disabled there because gitleaks is already authoritative.
